# Step 02: SHA-256 hashing and safe reads

- **Phase:** step 2 of 8 (see `docs/backup-plan/PLAN.md`)
- **Spec sections to read:** `docs/cfa-spec.md` §1.2, §6.2, §5 (why `mtime` is carried), §7 (why `sha256` is indexed)
- **Depends on:** 01

## Goal
A streaming SHA-256 primitive exists, refuses to return a hash for a file that changed while it was being read, and `BackupRecord` has somewhere to store the result. **Nothing calls it yet** — step 5 is the first consumer.

## Context
- Spec §1.2: "Compute a SHA-256 hash of each file before upload." §6.2: "Hash each remaining file (streaming SHA-256). If the file changes during reading (size or mtime differs afterward), skip it and log it." Note there is **no retry** in v2.0 — skip and log, once.
- `worker/app/fingerprint.py` and `web/app/fingerprint.py` are 19-line mirrors of each other (only a comment differs). They hold `compute_fingerprint`, a size + first/last-1 MiB BLAKE2b digest used as the catalog's cheap content identity.
- That fingerprint is **not** a substitute for SHA-256: it is partial, so it cannot key the index (§5) or be verified on restore (§7). The two coexist — fingerprint stays the catalog's fast identity, SHA-256 becomes the backup's real one.
- `BackupRecord.local_checksum` (`web/app/models.py:177`) holds a fingerprint, and `worker/app/tasks.py:119,410` set it. Its comment explains it is compared against the live `MediaFile.fingerprint` to detect source drift. **Leave all of that alone.**
- Step 01 established the pattern for additive columns: mirrored model changes, an idempotent `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` guard in `on_startup` (`web/app/main.py:83-90`), and an `assert_columns_mirrored` test using `web/tests/model_sync.py`.

## Changes

### `worker/app/fingerprint.py` and `web/app/fingerprint.py` (mirror both)
Keep `SAMPLE_SIZE` and `compute_fingerprint` byte-for-byte as they are. Append:

```python
HASH_CHUNK_SIZE = 4 * 1024 * 1024


@dataclass(frozen=True)
class HashedFile:
    sha256: str
    size_bytes: int
    mtime_ns: int


class FileChangedDuringRead(Exception):
    """A file's size or mtime moved while it was being hashed, so the digest
    cannot be trusted to describe any single version of it."""


def sha256_file(path: Path) -> str:
    """Streaming SHA-256 of the whole file (spec section 1.2)."""


def hash_file(path: Path) -> HashedFile:
    """sha256_file plus the spec section 6.2 guard: stats before and after,
    and raises FileChangedDuringRead if size or mtime_ns moved."""
```

- `sha256_file` reads in `HASH_CHUNK_SIZE` blocks via `hashlib.sha256`. 4 MiB rather than the existing 1 MiB `SAMPLE_SIZE`: fewer syscalls on multi-GB movies, still trivial memory. Use a `while chunk := f.read(HASH_CHUNK_SIZE):` loop.
- `hash_file` must be structured as **stat → `sha256_file(path)` → stat**, calling `sha256_file` as a module-level function (not an inlined loop), because the tests monkeypatch it to simulate a file changing mid-read.
- Compare `st_size` and `st_mtime_ns` before and after. On mismatch raise `FileChangedDuringRead` with a message naming the path and both observed (size, mtime_ns) pairs — the caller logs it, so the message has to be self-sufficient.
- Raising rather than returning `None` is deliberate: step 5's run loop must not be able to skip the check by ignoring a return value. Say so in a comment.
- `HashedFile` carries size and mtime because step 5 needs the values that were actually hashed, not a later re-stat: §5's index entry has an `mtime` field and step 7's skip-check compares against it.
- Add `from dataclasses import dataclass` where needed. Keep the two files' divergence limited to the existing top-of-file comment, as today.

### `web/app/models.py` and `worker/app/models.py` (mirror both)
On `BackupRecord`:
- `sha256: Mapped[Optional[str]] = mapped_column(String(64), index=True)` — indexed because §7 restores by hash lookup.
- `mtime_ns: Mapped[Optional[int]] = mapped_column(BigInteger)`

Comment both as written by step 5 and read by steps 6 and 7, nullable because every existing row predates the v2 pipeline. Note next to `sha256` that `local_checksum` is a different thing (a partial fingerprint) and is not being replaced.

### `web/app/main.py`
Two more guards in the step-01 block in `on_startup`:
```python
db.execute(text("ALTER TABLE backup_records ADD COLUMN IF NOT EXISTS sha256 VARCHAR(64)"))
db.execute(text("ALTER TABLE backup_records ADD COLUMN IF NOT EXISTS mtime_ns BIGINT"))
db.execute(text("CREATE INDEX IF NOT EXISTS ix_backup_records_sha256 ON backup_records (sha256)"))
db.commit()
```
The explicit `CREATE INDEX IF NOT EXISTS` is needed because `ADD COLUMN` does not create the index that `index=True` implies on a fresh `create_all`.

## Notes for the Implementer
- **Nothing calls the new functions.** If you find yourself editing a worker task or `catalog.py` to hash files, stop — that is step 5.
- `hash_file` must call `sha256_file` as a module attribute so `monkeypatch.setattr` can replace it. If you inline the hashing loop inside `hash_file`, two of the tests become unwritable — that is the reason for the split, not style.
- Use `st_mtime_ns`, never `st_mtime`. Float seconds lose precision and would make the step-7 skip-check miss fast edits.
- The empty-file case matters: `while chunk := f.read(...)` on a 0-byte file must still produce the empty-string digest, not raise or return `""`.
- Keep `String(64)` for the hex digest, matching the length-documented style the step-01 columns established.
- Do not add a `sha256` column to `MediaFile`. The hash describes what was backed up, not what is cataloged, and §6.1's skip-check uses path/size/mtime — not a hash.
