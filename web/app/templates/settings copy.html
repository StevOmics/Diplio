    Backup encryption

    When enabled, new backups are encrypted (AES-256-GCM) with a key derived from the passphrase below before being written to the backup location - useful if the backup destination isn't fully trusted (e.g. remote/cloud storage). Each file gets its own derived key; nothing but the passphrase itself needs to be kept safe. If you lose the passphrase, encrypted backups cannot be recovered.

    Error handling & Network performance

    If a backup or restore transfer fails, it's retried immediately with a short delay between attempts, up to Retry attempts times. If it continues to fail, the job is parked with a failed status and will be picked back up automatically after Retry interval — and again after that, until it succeeds or you manually intervene. Optionally limit the transfer speed to avoid saturating your network.

    Cloud storage (Google Cloud)

    {% set cs = cloud_storage_config %}

    Connect a Google Cloud Storage bucket to use as a second, off-site backup destination alongside (or instead of) a local one.

    1. Configure a service account

    In Google Cloud Console, create a dedicated service account for MediaBridge (IAM & Admin → Service Accounts → Create), then grant it one of:

    • Storage Admin (roles/storage.admin) at the project level — lets MediaBridge list your buckets so you can pick one below. Simplest to set up.
    • Storage Object Admin (roles/storage.objectAdmin) scoped to a single bucket only — tighter, but MediaBridge can't list buckets with this role, so you'll type the bucket name in manually instead of picking from a list.

    2. Get service account credentials

    On that service account, create a JSON key (Keys → Add key → Create new key → JSON) and upload the downloaded file here.
